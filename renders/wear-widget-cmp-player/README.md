# Wear widget previews on the CMP player — render evidence for #5259

The four `:samples:wear-widget` previews that go through `CapturingWearWidgetPreview` drawn twice on
this branch, from the **same captured `RemoteDocument`**, differing only in which player replays it:

* `*-before.png` — `-PcomposePreview.wearWidgetPlayer=view`, upstream `WearWidgetPreview`'s
  `AndroidView`-hosted `RemoteComposePlayer`. This is what every widget preview drew before this
  change.
* `*-after.png` — the new default (`cmp`), the vendored embedded Compose player
  (`ExperimentalRemoteDocumentPlayer` → `RcPlayer`).

| Preview | Frame | `-before.png` | `-after.png` |
|---|---|---|---|
| `ImageWidgetSquirclePreview` `PARAM_0` | 364×152 | View player | CMP player |
| `ImageWidgetSquircleLargePreview` `PARAM_1` | 432×248 | View player | CMP player |
| `ImageWidgetFixedPreview` | 567×200 | View player | CMP player |

**Every frame is the same size on both lanes**, which is the load-bearing property: `RcPlayer`
renders into the constraints it is given rather than measuring itself from the document header, so
`CapturingWearWidgetPreview` states upstream's own size —
`(widthDp + 2·horizontalPaddingDp) × (heightDp + 2·verticalPaddingDp)` — around it. Switching
players therefore moves pixels *within* the frame and never the frame itself. Measured across all
ten rendered PNGs (the seven `@PreviewParameter` fan-out members included), before and after agree
on width and height in every case.

Within the frame the two differ, as two independent rasterisers of one document do — anti-aliasing
along the squircle edge and the glyph rasterisation of the label. Nothing about the widget's
content, gradient or layout changes.

## What the change is actually for

The accessibility report, same module, same machine, `compose-preview a11y --module
:samples:wear-widget` with a cleared `data/` + `renders/` between runs:

| Player | Findings |
|---|---|
| `view` (before) | **5** — `SpeakableTextPresentCheck` against `androidx.compose.remote.player.view.RemoteComposePlayer`, one per preview |
| `cmp` (after, default) | **1** |

The four that go away are the ones routed through `CapturingWearWidgetPreview`
(`ImageWidgetSquircle`, `ImageWidgetSquircleLarge`, `ImageWidgetDeviceSpec`, `ImageWidgetFixed`).

The one that remains is `ActivitySummaryWidgetSquirclePreview`, and it is not covered by this
change: that file is generated by the UI builder's Wear-widget adapter (in
`yschimke/compose-preview-server`), which deliberately calls upstream `WearWidgetPreview` directly
rather than this repository's wrapper — it wants a frame, not a captured document, and does not
want `wear-preview-runtime` on the list of things a bundle must carry. Moving that lane onto the
CMP player is a change in that repository's generator plus a fixture regeneration here.
