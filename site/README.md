# Documentation site analytics

The production Pages build optionally reads repository Actions variables `UMAMI_ENABLED`,
`UMAMI_URL` and `UMAMI_WEBSITE_ID`. Analytics is off by default, even with URL/ID configured.
Enable it explicitly with `UMAMI_ENABLED=1` (or `true`). Local Jekyll builds never load it.
For our deployment, the endpoint is `https://preview.coo.ee/__analytics` and the website ID is
the `yschimke.github.io` entry generated by `deploy/analytics/bootstrap.py` in compose-preview-server.

The checked-in `assets/analytics.js` is the standalone generated analytics bundle from
compose-preview-server (`serve-web/src/analytics.ts`). It is shared with the preview viewer and
builder shell. To update it, build that repository's serve-web package and copy
`server/src/main/resources/ee/schimke/composeai/cli/serve/assets/analytics.js` here. Include the
source commit in this document when updating the bundle.

Current source: [compose-preview-server 3ca304a1](https://github.com/yschimke/compose-preview-server/commit/3ca304a1).

It records page views and link navigation categories, respects Do Not Track and Global Privacy
Control, and drops query strings, fragments, page titles and referrers. Search input, source code
and link URLs are not recorded as event properties. No session replay is enabled.

Analytics is optional: the docs still work when the collector is down or blocked. Hosting remains
on GitHub Pages. Set `UMAMI_ENABLED=0` and rerun the Pages workflow to disable it without losing URL/ID settings.
