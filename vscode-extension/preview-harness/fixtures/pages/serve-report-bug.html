Report a bug in the preview server

This files against yschimke/compose-ai-tools, the repository that ships compose-preview serve as @yschimke — the page you were on, its controls, and the render lanes behind them.

Wrong pixels rather than a wrong page? A button in the wrong colour, a state that is missing, a spec that does not match — that is the catalog’s bug, not this server’s. Go back to the preview and use its “report a catalog issue” link, which files against the repository whose Kotlin declares that preview. A catalog bug filed here reaches people who cannot fix it.

Opens GitHub’s new-issue form. Nothing is sent from this server — you write the description and press Submit there.

Add a screenshot

The report has a Screenshot section waiting for one. Paste it into that section on GitHub — it uploads to GitHub’s own storage, so it keeps showing what you saw even after this server changes.

No captures came across from the page you reported. Take one there with the “Report a problem” button, or paste an ordinary screenshot straight into the issue.
