compose-ai-tools

Let your coding agent see the Compose UI it just changed.

compose-ai-tools renders your @Preview composables to PNG outside Android Studio, so your agent can look at its work, and so can you. Jetpack Compose (Android) and Compose Multiplatform Desktop.

Get started Reference GitHub

Get started

Pick your agent and run its one install.

Claude Code

/plugin marketplace add yschimke/compose-agent-plugins
/plugin install compose-preview@compose-agent-plugins

Codex

codex plugin marketplace add yschimke/compose-agent-plugins

then enable compose-preview from /plugins.

Antigravity

curl -fsSL https://raw.githubusercontent.com/yschimke/compose-agent-plugins/main/scripts/antigravity-install.py | python3 -

Any other agent (Gemini CLI, OpenCode, Cursor, Copilot, …), or no plugin system:

curl -fsSL https://raw.githubusercontent.com/yschimke/skills/main/scripts/install.sh | bash

Then: ask your agent to render one of your previews. That’s the whole onboarding.

Designing a new screen instead? Start at https://ui.coo.ee/start.

Other hosts and install options

Without an agent

VS Code (or Cursor / Windsurf / VSCodium): search the Extensions view for Compose Preview and click Install. It renders previews inline and needs no project changes. (Marketplace · Open VSX)

Command line. The install.sh one-liner above also installs the compose-preview CLI. Point it at any Compose project, no build edits required:

compose-preview render    # render every @Preview to PNG
compose-preview browse    # Storybook-like local component catalog

Gradle plugin. Prefer a version-pinned plugin in your build? It’s on Maven Central — no auth, no token. Replace <published-version> with the version shown there.

// <module>/build.gradle.kts
plugins {
    id("ee.schimke.composeai.preview") version "<published-version>"
}

./gradlew :app:composePreviewRenderAll   # render every @Preview to PNG

Render filters, CI recipes and requirements are on the Install page.

When you need more

None of this is required to get value from the tool. Your agent will offer the relevant one when it comes up.

  • PR review and preview CI. Before/after renders posted on every pull request by the apply action, and the compose-preview-review and compose-preview-ci skills that review a UI PR and set that CI up. Claude Code: /plugin install compose-review@compose-agent-plugins; elsewhere, install.sh --skills compose-preview-review,compose-preview-ci.
  • UI Builder — design a new screen with an agent in the browser, then export it as Compose code.
  • Android simulator — compose-preview android-simulator app.apk runs a whole APK without an emulator: permissions, notifications, home-screen widgets, and Wear OS tiles, complications, watch faces and a paired phone.
  • Data products — structured data alongside each PNG: accessibility findings, layout trees, theme tokens, recomposition heat maps, drawn text, and more.
  • Agents & MCP — the local and hosted MCP servers, and a token-frugal agent loop over Compose UI (semantic refs, semantics diffs, recording to tests).
  • Daemon — a long-lived renderer that keeps Robolectric / Compose-Desktop warm so re-renders are fast.

More

  • How it works — discovery, renderer pipeline, caching.
  • Benchmarks — measured latency, memory, and fidelity against android preview and android studio render-compose-preview.
  • Samples — rendered baselines for samples:android, samples:wear, samples:cmp, samples:remotecompose, regenerated on every push to main.
